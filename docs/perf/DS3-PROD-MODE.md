# DS3: «боевой» режим — убрать нагрузку от диагностики, оставить [gpu-perf] и [xp]

Дата: 20.10.2026. Исходники: `<build-tree>/src` @ b8a21b3 (DXMT ceccaa9, wine 9129e968), FEX `<build-tree>/fex-src` @ f59cab9.
Журналы: `logs/ds3/DarkSoulsIII.exe-2026-10-20_21-35-10.txt` (бой: строки 35134–111890, 292 с, 19.9 fps)
и `…_22-17-46.txt` (бой: 31244–98730, 275 с, 16.5 fps). Время окна посчитано по сумме мс в строках `[gpu-perf]`
(у большинства строк журнала нет метки времени).

Пометки: **[факт]** — из исходников или посчитано по журналу; **[оценка]** — моя прикидка стоимости, не мерил.

## Главный вывод

- Запись журнала сама по себе дешёвая: в бою **263 строки/с, 36 КБ/с** [факт]. Строка = форматирование + `write(2)`
  (PE-код ещё и переход PE→unix) — порядка 5–15 мкс [оценка] → ~0,3 % одного ядра на все потоки.
- Главный поток игры (00ac) занимает **~79 % ядра** (P 63,5 % + E 15,2 %, сумма `[xp-t]` за окно) [факт].
- Конфиг ниже снимает с главного потока **~1–2,5 %** его работы [оценка] — это **+0,2–0,5 fps** при 20 fps — и убирает
  периодические рывки (раз в 20 с — заморозка всех потоков выборщиком, раз в ~минуту — обход всей памяти на 0,7–0,8 с).
  Чуда не будет: упор — в реальную работу (см. «Что не лечится конфигом»).
- `[xp]` стоит **~0,2–0,4 % одного ядра** [оценка], потоки не останавливает, работает в своём фоновом потоке → оставляем.
  На нём же держится кэп FPS (`ios_fps_gov_step` вызывается внутри `ios_xprobe_main`, server_ios.c) [факт].

Реальные частоты событий под выборками (по счётчикам в строках) [факт]: SMC 462/с, `[rtcs]` 462/с, неперехваченные
нарушения доступа 717/с, BUS 356/с, UNALIGNED 66/с, всего исключений Mach **~2 700/с** (`mach_exc=` 79 277 → 255 786 за 64,5 с),
сброс стека call/ret FEX 964/с, освобождение 2-МБ регионов 868/с.

### Как пишется журнал [факт]
- Wine/DXMT/FEX: `__wine_dbg_output` → unix `write(2, …)` построчно, синхронно, в `madeira-log.txt` (stderr через `dup2`,
  WineProcessBridge.m:1332-1341). Буфера/кольца нет.
- `wine_log_write` (server_ios.c:57): `vsnprintf` + `dprintf(2)` + обратный вызов в Swift (`wine_ui_log`, со строкой и
  выделением памяти; при свёрнутом журнале UI сразу выходит — в логе `[ui-log-idle] … suspended=1`).
- DXMT: `ERR(...)` = `Logger::err(str::format(...))` — **строка собирается до проверки уровня**, так что
  `DXMT_LOG_LEVEL=none` форматирование не убирает (log.hpp:88, log.cpp:47).
- FEX на iOS: `FEX_SILENTLOG` вырезан (`#ifndef FEX_IOS_HOST`, Source/Windows/Common/Logging.cpp:90) — **заглушить FEX нечем**.

## 2. Ручки [факт — проверено в исходниках, если не сказано иное]

| Ручка | Что выключает | Что остаётся |
|---|---|---|
| `env.MADEIRA_LEAN_DIAG = 1` | выборщики с остановкой потоков (`[thread-sample]` всплески, `[rip-profile]`, `[cpu-split]`, `[wprof]`); обход памяти warmer'ом раз в ~10 мин вместо ~1 мин (`MADEIRA_WARMER_SWEEP_CYCLES` 300 вместо 30); строка mprotect_exec 1/1000 | **`[xp]`, `[xp-t]`, `[xp-api]`, `[sync-census]` — без изменений**; кэп FPS работает (xprobe запускается всегда, server_ios.c:5733) |
| `env.WINEDEBUG = err+all,err-virtual,err-seh,fixme-all` | `[rtcs] pre` уже на этапе проверки канала (без форматирования и перехода в unix), `[exc]`, `bus_handler`, `D3DPERF_GetStatus` и прочие fixme | ошибки остальных каналов. Строка игры побеждает умолчание Madeira (`setenv(...,1)` после WineProcessBridge.m:949) |
| `env.DXMT_LOG_LEVEL = error` | info/warn DXMT (в бою 0,6 строки/с) | **`[gpu-perf]` остаётся**: печатается через `ERR(line)` (dxmt_command_queue.cpp:252-262), а `error` пропускает уровень Error (log.cpp:47). `none` убил бы и его |
| `env.DXMT_CENSUS_THROTTLE = 1` | отчёт памяти DXMT (93 строки/с) → 1 раз в 10 с (кроме «warn» — всегда) | память DXMT в журнале раз в 10 с (dxmt_mem_census.cpp:196-221) |
| `env.MADEIRA_STUCK_WAIT_SECS = 86400` | `[srv-stuck]` + связка `[evt-*]` на потоке wineserver (порог ожидания, queue_ios.c:4437-4441) | `[srv-queues]` раз в 10 с в режиме рабочего стола (своей ручки нет) |
| `env.MADEIRA_RTCS_LOG = 0` | только запись `[rtcs]`, не форматирование | — (лишнее при `err-seh`) |
| `env.MADEIRA_FPS_CAP = 30` | — | требует `[xp]` (он и не выключается) |

Не трогать: `MADEIRA_DESKTOP` (это не диагностика — режим рабочего стола), `MADEIRA_QUIET` (уже `1`, ставит сама Madeira).

## 4. Боевой блок (вставить в Game details › Advanced › This game's config)

```
# DS3 боевой режим (20.10.2026): меньше диагностики, [gpu-perf] и [xp] остаются
env.MADEIRA_LEAN_DIAG = 1
env.WINEDEBUG = err+all,err-virtual,err-seh,fixme-all
env.DXMT_LOG_LEVEL = error
env.DXMT_CENSUS_THROTTLE = 1
env.MADEIRA_STUCK_WAIT_SECS = 86400
```
Строки, которые уже есть в конфиге игры (`MADEIRA_EC_HOOK_TRACE=0`, `LOCK_ORPHAN`, `X64_IMAGE_NOCOPY`, `pool-split`), — оставить.

**Ожидание** [оценка]: главный поток −1–2,5 % работы (журнал на нём ~0,5 %, остановки выборщика ~0,5–1 %, конкуренция
с обходом памяти ~0,5 %); fps +0,2–0,5; пропадают рывки раз в 20 с и раз в минуту. Журнал: **−57 % строк** (150 из 263/с),
36 → ~18 КБ/с [факт: пересчёт по окну боя].

**Что остаётся**: `[gpu-perf]` (fps, GPU busy, draws), `[xp]`/`[xp-t]`/`[xp-api]` (мощность, частоты, CPU по потокам),
`[sync-census]`, `[freeze]`, `[thermal]`, кэп FPS. **Что теряется**: строки ошибок канала seh (`SEGV LOOP FATAL`,
`[exc]`) — при разборе вылета убрать `err-seh` из WINEDEBUG.

**Проверка после запуска** (одной командой по журналу): есть `[lean-diag] madeira-bcd MADEIRA_LEAN_DIAG=1`,
`[thread-sample] ml876 armed for [sync-census] only`, `[madeira-env] game WINEDEBUG=…`, `[gpu-perf]` и `[xp]` идут,
`[mem-census] ml678` не чаще раза в 10 с, `[rtcs]`/`D3DPERF` нет. Сравнивать fps по `[gpu-perf]` на той же сцене.

## 5. Что не лечится конфигом (настоящие потребители) [факт по журналу, вывод — версия]

- **~2 700 исключений Mach/с** (SMC anti-tamper 462/с, нарушения доступа 717/с, BUS 356/с): каждое — круг через поток-обработчик.
- **Сброс стека call/ret FEX 964/с** на главном потоке, каждый — `madvise` 8 МБ (Core.cpp:744) и повторное заполнение
  страниц. Стоит отдельного замера.
- Освобождение/выделение 2-МБ регионов ~860/с (`[iOS-xrem]` #, `[commit-zero]` #).
- 13–30 тыс. запросов/с главного потока к wineserver (`[sync-census]`, `[srv-req]`) — см. DS3-PERF-knobs.md, рычаги №1–2.
- Правка кода с наибольшей отдачей среди диагностики: убрать безусловный `mach_vm_region` из обработчика (п. 3).
