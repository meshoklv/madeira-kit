## 0. Как читать строки (сверено с исходником)

- `[xp]` (server_ios.c:2577) — каждые ~250–320 мс по процессу: `cpu`/`P`/`E` — **мс CPU за окно `dt`**
  (cpu/dt = число занятых ядер), `GHz P/E`, `Minst`, `IPC`, `run` (мс в очереди «готов, но не запущен»),
  `pgw` (ожидание страниц), `mJ` (энергия CPU процесса), `fpMB`.
- `[xp-t]` (server_ios.c:2600): `-<wtid>` — Windows-поток без роли, `m<mach id>` — нативный поток.
  Поля: **`P мс / E мс : ГГц P / ГГц E : Minst`** — последнее поле — **млн инструкций за окно, а не cpu %**
  (в задании было «cpu%» — неверно). Печатаются только 14 самых занятых потоков.
- `[xp-api]` — раз в секунду: переходы x64→EC (счётчик FEX), CS-контенция и WaitOnAddress (PE ntdll),
  unix-счётчики ожиданий. `[xp-api-top]` — адреса **целей** x64→EC-вызовов (кольцо 4096 выборок).
- `[CB_SUMMARY]` — **общий на процесс** счётчик (`g_cb_real_compiles` в xtajit64.dll), печатает поток,
  перешагнувший очередные 16384 поиска; `real_compiles` — реальные компиляции блоков FEX.
- `[smc] ml1055 N` — накопительный счётчик обработанных записей в код (строка на каждую 1000-ю).
- `[rtcs-cap] (N seen)` — накопительный счётчик исключений, прошедших `prepare_exception_arm64ec`.
- Исходников FEX в `<build-tree>/src/FEX` нет (подмодуль не выкачан) — форматы FEX-строк взяты
  из строк внутри `app/Madeira/arm64ec-windows/xtajit64.dll`.

Адреса из `[xp-api-top]` сверены с экспортами `arm64ec-windows/ntdll.dll`/`kernelbase.dll`
(через x64-заглушки `mov rax,rsp … jmp`) **[факт]**:
`ntdll+0x6784c` = RtlEnterCriticalSection, `+0x67dcc` = RtlLeaveCriticalSection,
`+0x71aac` = RtlQueryPerformanceCounter, `+0x281ac/0x27cc8` = RtlAllocateHeap/RtlFreeHeap,
`kernelbase+0x6d470` = TlsGetValue, `+0x68a34` = WaitForSingleObject, `+0x69424/0x69470` = Set/ResetEvent.

## 2. Вопрос 1 — какие потоки жгут CPU [факт]

Доля одного ядра (P+E мс / длительность окна), по всем выборкам `[xp-t]` фазы:

| Поток | Меню (90 с) | Заставка (135 с) | Геймплей (105 с) |
|---|---|---|---|
| **00a8 (главный, он же D3D11-поток)** | **93 %** (303/312 выборок >90 %) | 74 % | **79 %** (P 70 + E 10) |
| m347452 (нативный, создан первым при старте wineserver — [версия] поток wineserver) | 8 % | 21 % | 13 % |
| 014c/0150/0154/0158/015c (5 рабочих потоков) | ~0 | 16–18 % каждый | ~9 % каждый |
| 0128 / 00b8 / 0100 / 0134 / 0148 | 2–4 % | 4–15 % | 5–8 % |

- **Главный поток 00a8 — предел.** В геймплее 286 из 354 выборок в полосе 80–90 %, 19 выше 90 %,
  15 почти простой (подгрузки). Остальные ~15 % — ожидания (CS/сервер), см. §4.
- Главный поток в геймплее: **6 070 млн инстр/с при ≈11 FPS ≈ 530 млн инструкций на кадр**, IPC ≈ 4.1,
  частота 1.75 ГГц. То есть он упирается в **объём работы × частоту**, а не в память (pgw = 0).
- В меню его «93 %» — **холостой спин**: 88 % выборок `[rip-profile]` — в QueryPerformanceCounter,
  20–21 млн QPC/с от 00a8 (ограничитель кадров игры крутится в цикле). Это греет чип в меню/заставках.
- Весь процесс в геймплее — 2.0–2.4 ядра из 6; E-ядра заняты на 0.5–0.8.

## 6. Вопрос 5 — топ-3 пожирателя CPU и рычаги

**1. Вызовы CriticalSection через переход x64→EC на главном потоке.** [факт] 1.6 млн пар/с,
24–53 % выборок главного потока. Рычага в `ConfigCatalog` нет: `MADEIRA_FEX_EC_EXIT_LEAN`,
`EC_RET`, `EC_RET_DIRECT`, `EC_BITMAP_CACHE` уже включены (`ec-exit-lean-v1 enabled=true` в логе).
Косвенно: `env.FEX_TSOENABLED = 0` удешевит атомарные операции внутри CS [версия, риск: FEX сам пишет
«скорее всего сломает многопоточное приложение»]. Реальное лечение — код: быстрый путь
незанятой CS без выхода из JIT (задача для Madeira/FEX, не настройка).

**2. Синхронизация через wineserver (мьютексы/семафоры/ожидания).** [факт] 4–10 тыс. рейсов/с с
главного потока + поток сервера 13 % ядра + CS-ожидания 95 мс/с. Рычаги (из каталога/списков игр):
`inproc-sync = 1` (madsync: мьютексы в процессе), или `env.MADEIRA_SRV_DIRECT = 2` (запросы на
вызывающем потоке, без переключений), плюс `env.MADEIRA_FASTSYNC_SEM = 1` (так в списке GTA V outside
Steam). Выигрыш [версия]: при 10–20 мкс на рейс — 5–20 % главного потока.

**3. Перекомпиляция JIT из-за самоизменяющегося кода anti-tamper + сжатие буфера кода.** [факт] 1 000–1 200
компиляций/с (пик 3 317/с сразу после сжатия буфера до 16 МБ), 200–244 SMC-записей/с, ~330 ошибок
защиты/с. Рычаги: убрать сжатие буфера — `pool = 1152` (глобально), `env.MADEIRA_X64_IMAGE_NOCOPY = 1`,
`pool-low = 1` + `env.MADEIRA_POOL_LOW_IMAGES = 1` + `env.MADEIRA_POOL_RECYCLE_IMAGES = 1`
(все — из списков RDR2/GTA V) [версия по эффекту]. Сам SMC настройкой не убрать
(`MADEIRA_FEX_SMC_FASTPATH` уже вкл., `FEX_SMCCHECKS=none` сломает защиту игры); других рычагов
в рамках Madeira нет.

Фон: частота P-ядер в геймплее 1.5–1.85 ГГц против 3.1–3.4 в лёгких сценах. Спин QPC в меню и 90 % GPU
на заставке греют чип до геймплея — `env.MADEIRA_FPS_CAP = 30` для меню/заставок (рычаг №3 в
`DS3-PERF-knobs.md`). `env.MADEIRA_LEAN_DIAG = 1` снимает выборщики, останавливающие главный поток.
